# AI Tooling Disclosure

HangarSweep was built with significant assistance from AI coding tools. This document provides transparent accounting of how those tools were used, in accordance with best practices for AI-assisted open source development.

## Scope of AI Involvement

### Architecture and design
The overall architecture — Tauri 2.0 desktop app, Rust backend, React TypeScript frontend, SQLite with embedded migrations, OAuth 2.0 PKCE flow — was designed collaboratively with AI assistance. The AI suggested the approach; the developer evaluated and approved it.

### Code generation
The majority of boilerplate and implementation code was generated by AI based on high-level descriptions of the desired behaviour. This includes:
- Rust modules: `auth.rs`, `esi.rs`, `db.rs`, `commands.rs`, `lib.rs`
- React components: `App.tsx`, `CharacterHeader.tsx`, `LocationList.tsx`, `AssetDetail.tsx`
- CSS: `app.css`
- GitHub Actions workflows
- Test suites

### Debugging
Several non-trivial bugs were diagnosed and resolved with AI assistance:
- **ESI 404 batch poisoning**: `resolve_names()` was sending ship/container item IDs (100M–1T range) mixed with NPC station IDs to `POST /universe/names/`. ESI returns 404 for the entire batch if any single ID is unresolvable. Fix: filter `location_id < 100,000,000` (NPC-only) before batching; resolve types and stations in separate requests.
- **Tauri 2.0 IPC camelCase**: Rust `snake_case` parameters are automatically renamed to `camelCase` in the JavaScript IPC layer. All `invoke()` calls must use camelCase keys.
- **OAuth redirect URI mismatch**: EVE SSO requires an exact match on the callback URL including port; updated to `http://localhost:57423/callback`.
- **MSVC linker discovery**: Pinned `link.exe` path in `.cargo/config.toml` to ensure consistent builds across shells without PATH manipulation.

### Documentation
README, CHANGELOG, SECURITY, CONTRIBUTING, and this disclosure were written with AI assistance and reviewed by the developer.

## What AI Did Not Do

- Make product decisions (what features to build, what EVE data to surface, threshold values)
- Test the application against live EVE characters and real ESI responses — all integration with the live EVE API was performed by the developer
- Access the developer's EVE account credentials
- Submit code to GitHub — all commits were reviewed and pushed by the developer

---

## Why Disclose?

AI-generated code carries the same responsibility as human-written code: it must be reviewed, understood, and tested. Disclosing AI involvement:

1. Helps reviewers calibrate their scrutiny appropriately
2. Sets honest expectations for code provenance
3. Contributes to evolving norms around AI transparency in open source

If you find a bug, the AI didn't ship it — we did. PRs and issue reports are welcome.

---

## Verification

The test suites in this repository (`cargo test`, `npm test`) were written to verify the correctness of the AI-generated logic independently. Where AI-generated code was later found to be incorrect (see debugging cases above), fixes were applied and regression tests added.
